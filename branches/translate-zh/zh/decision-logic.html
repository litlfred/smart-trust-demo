    决策支持逻辑是 DAK 的第 6 个组成部分：各旅程所作出的决策，按照 世卫组织 SMART 指南（WHO SMART Guidelines）DAK 的写法，以 OMG 决策模型和表示法（Decision Model and Notation）（DMN 1.3）中的决策表表示。每个表都指明它所服务的业务流程任务、它所应用的需求、它所读取的数据元素，以及在示例中展示它的 FHIR 工件。每个表也是一个 PlanDefinition（类型 eca-rule），每条规则对应一个动作，因此它列在工件索引中。

    源文件为 processes/content/decisions/*.dmn；本页面和各 PlanDefinition 均由其生成。各条目使用工具框架决策表解释器所接受的 FEEL 子集：-（任意）、字面量、比较以及 one-of。每个表的命中策略都是 FIRST：按顺序尝试各规则，第一条匹配的规则生效，因此顺序是逻辑的一部分。凡规则写明“根据国家政策”之处，该政策指本国的政策；这些表用于说明决策，并非某个国家的规则。

    决策表 服务于 需求
    TD.DT.01 扫描的 DVC 在儿童记录中成为什么？ J2 在 B 国发现并转诊未登记的婴儿：以未验证方式读取每个 DVC（分诊）（Task_Read）；添加婴儿；将剂次保存为已报告（Task_Register）J3 在所属诊所验证、导入并安排接种计划：针对信任列表验证每个 HCERT（Task_Verify）；每个 DVC 都已验证？（Gateway_Verified）；记录失败；按政策决定剂次（Task_Unverified）；将剂次作为 FHIR Immunization 资源导入（Task_Import） STT-VER-001，STT-VER-006，STT-VER-008，STT-VER-011
    TD.DT.02 导入的剂次带有哪个国家接种计划编码？ J3 在所属诊所验证、导入并安排接种计划：在外国编码旁添加国家编码（Task_Map） STD-SEM-001

    TD.DT.01 扫描的 DVC 在儿童记录中成为什么？

    根据读取某个外国 DVC 的结果，决定其剂次是记录为已验证、保留为已报告且未验证，还是根本不据此记录。

    • 服务于：J2 在 B 国发现并转诊未登记的婴儿：以未验证方式读取每个 DVC（分诊）（Task_Read）；添加婴儿；将剂次保存为已报告（Task_Register）；J3 在所属诊所验证、导入并安排接种计划：针对信任列表验证每个 HCERT（Task_Verify）；每个 DVC 都已验证？（Gateway_Verified）；记录失败；按政策决定剂次（Task_Unverified）；将剂次作为 FHIR Immunization 资源导入（Task_Import）
    • 需求：STT-VER-001，STT-VER-006，STT-VER-008，STT-VER-011
    • 数据元素：TD.J3A.DE05 验证结果，TD.J3A.DE07 失败原因，TD.J3A.DE09 记录结果
    • 示例中：StructureDefinition TrustDemoOnesaReportedImmunization、StructureDefinition TrustDemoOnesaDvcVerification、Provenance TrustDemoJ3Verification
    • 可计算形式：PlanDefinition TrustDemoDT01；源文件 dvc-record-outcome.dmn，命中策略 FIRST
    # 验证结果（result） 失败原因（failureReason） 记录结果（outcome） 动作（action） 注释
    1 unverified 任意 reported-unverified 将该剂次保存为由家庭报告的剂次（primarySource false，照护者作为信息来源，并注明未经任何验证），并将儿童转诊到诊所进行验证。 J2 中 CHW 的分诊读取（STT-VER-011）：未验证任何内容，因此该剂次是已报告的，绝不是已验证的。示例 Immunization TrustDemoJ2HepBReported。
    2 verified 任意 verified 以 primarySource true 导入该剂次，并附带一个验证 Provenance，其中指明签名者的密钥，并移除被其替换的已报告剂次；然后映射其疫苗编码（TD.DT.02）。 J3 的“是”路径（STT-VER-001）：该剂次根据其原始来源记录。示例 Immunization TrustDemoJ3HepB 和 Provenance TrustDemoJ3Verification。
    3 failed KidNotFound reported-unverified 将该剂次保留为已报告；记录步骤和原因（STT-VER-008）；在下次信任列表刷新后再次验证该 DVC。 签名者的证书不在诊所缓存的信任列表中（STT-VER-006），例如在上次刷新之后添加的签名者：即 J3 的“否”路径“直到下次刷新”。
    4 failed Expired、NotYetValid 之一 reported-unverified 将该剂次保留为已报告；记录步骤和原因；由临床医生根据国家政策决定是否接种或重复接种该剂次。 签名已验证，但证书超出其有效期。该剂次未被验证；由临床医生根据国家政策决定。
    5 failed BadPrefix、UnsupportedContextVersion、Base45Invalid、InflateFailed、LimitExceeded、CoseMalformed 之一 not-read 重新扫描；如果仍然失败，则将该卡片当作纸质记录对待，并记录其未被验证的原因。 解码在任何签名检查之前就已失败（按 STT-VER-001 的顺序），因此未读取任何内容：这是三种状态而不是两种，因为扫描失败不能证明任何一方面。
    6 failed 任意 rejected 不要根据该证书记录剂次；记录步骤和原因；由临床医生根据国家政策决定，与无记录剂次的处理方式相同。 任何其他失败（签名、密钥用途、头部、算法、hcert 声明或载荷）：该证书不构成剂次的证据。

    TD.DT.02 导入的剂次带有哪个国家接种计划编码？

    对于某一剂次，决定是否以及如何在签发方的产品编码（始终保留）旁添加国家接种计划编码。

    • 服务于：J3 在所属诊所验证、导入并安排接种计划：在外国编码旁添加国家编码（Task_Map）
    • 需求：STD-SEM-001
    • 数据元素：TD.J3A.DE09 记录结果，TD.J3B.DE01 签发方的产品编码，TD.J3B.DE02 国家接种计划编码，TD.J3B.DE03 映射依据
    • 示例中：ConceptMap TrustDemoProductToOnesaEpi、Provenance TrustDemoJ3Adjudication、Immunization TrustDemoJ3HepB
    • 可计算形式：PlanDefinition TrustDemoDT02；源文件 vaccine-code-mapping.dmn，命中策略 FIRST
    # 记录结果（TD.DT.01）（outcome） 国家映射表中的条目（mapEntry） 临床医生确认对应项（clinicianConfirms） 映射依据（mappingBasis） 动作（action） 注释
    1 reported-unverified、rejected、not-read 之一 任意 任意 not-imported 不添加接种计划编码。 只有已验证的剂次才会被导入和映射（J3 的“是”路径）；已报告的剂次仅保留签发方的编码。
    2 verified equivalent 任意 concept-map 在产品编码旁添加映射得到的接种计划编码。 STD-SEM-001（映射）：已发布的国家映射表中有对应项；两种编码都保留，如 TrustDemoJ3Bcg 所示。
    3 verified none yes clinician-confirmed 在产品编码旁添加经确认的接种计划编码；将临床医生的认定记录为 Provenance；将该编码对添加到国家映射表中。 映射表中没有条目，由临床医生确认对应项（J3：Hep B 产品）。她的决定被记录并添加到映射表中，这样下一家诊所就无需重复。
    4 verified none no unmapped 保持产品编码不变，并将该剂次以未映射状态展示给临床医生；接种计划不计入该剂次（TD.DT.03）。 STD-SEM-001（未映射）：没有已知的对应项，也不作任何猜测。

    TD.DT.03 国家接种计划是否计入该剂次？

    对于儿童记录中的某一个 Immunization，决定接种计划评估是否将其计为已接种。

    • 服务于：J3 在所属诊所验证、导入并安排接种计划：评估国家接种计划（Task_Schedule）
    • 需求：STD-SCH-001，STD-SEM-001
    • 数据元素：TD.J3B.DE02 国家接种计划编码，TD.J3B.DE05 计入接种计划
    • 示例中：StructureDefinition TrustDemoOnesaImmunization、StructureDefinition TrustDemoOnesaReportedImmunization
    • 可计算形式：PlanDefinition TrustDemoDT03；源文件 dose-counts.dmn，命中策略 FIRST
    # 根据其原始来源记录（primarySource） 具有国家接种计划编码（hasScheduleCode） 计入（counts） 原因（why） 注释
    1 false 任意 false 已报告，未验证。 已报告的剂次（J2：TrustDemoJ2HepBReported）会显示，但不计入。
    2 true false false 未映射：展示给临床医生。 没有接种计划编码的已验证剂次（TD.DT.02 未映射）无法被接种计划读取，因为接种计划基于接种计划编码运行。
    3 true true true 按已接种计入。 STD-SCH-001：无论在何处接种，均按其接种计划编码和日期计数（J3：TrustDemoJ3HepB、TrustDemoJ3Bcg）。

    TD.DT.04 国家接种计划的该剂次是否到期？

    对于国家接种计划的某一个动作，决定评估是否建议现在执行，以及从哪个日期开始。

    • 服务于：J3 在所属诊所验证、导入并安排接种计划：评估国家接种计划（Task_Schedule）；接种到期剂次并预约下次就诊（Task_Plan）
    • 需求：STD-SCH-001
    • 数据元素：TD.J3B.DE05 计入接种计划，TD.J3B.DE07 接种计划剂次，TD.J3B.DE08 预测状态，TD.J3B.DE09 到期日期
    • 示例中：PlanDefinition TrustDemoOnesaInfantSchedule、ImmunizationRecommendation TrustDemoJ3Recommendation、Task TrustDemoJ3Reminder
    • 可计算形式：PlanDefinition TrustDemoDT04；源文件 dose-due.dmn，命中策略 FIRST
    # 已计入的剂次带有该动作的编码（TD.DT.03）（counted） 该动作的接种时间年龄是所有没有已计入剂次的动作中最早的（isNextVisit） 预测（forecast） 到期日期（dueDate） 注释
    1 true 任意 complete — J3：Hep B 和 BCG 出生剂次一经导入即计入，因此不会再次建议接种（STD-SCH-001）。
    2 false true due birthDate + timingAge J3：6 周时的五联疫苗第 1 剂、bOPV 第 1 剂和 PCV 第 1 剂，到期日 2025-12-09（ImmunizationRecommendation TrustDemoJ3Recommendation），并附带该日期的提醒 Task。
    3 false false not-yet — J3：9 个月时的麻疹-风疹第 1 剂属于之后的就诊，不在本次建议中。

    TD.DT.05 门户是否针对该请求释放清单？

    对于某一个清单请求（ITI-YY5），决定门户是否释放清单，以及访问日志记录什么。

    • 服务于：J4.1 在国外的医疗服务点读取家庭成员的记录：核验通行码、记录访问、返回清单（Task_Release）
    • 需求：STD-ACC-001
    • 数据元素：TD.J40.DE06 有效期至，TD.J40.DE09 撤回时间，TD.J41.DE06 已释放，TD.J41.DE07 审计结果，TD.J41.DE08 拒绝原因
    • 示例中：Consent TrustDemoJ4Consent、AuditEvent TrustDemoJ41Access、AuditEvent TrustDemoJ41WrongPasscode
    • 可计算形式：PlanDefinition TrustDemoDT05；源文件 vhl-release.dmn，命中策略 FIRST
    # 持有人撤回了链接（withdrawn） 请求在持有人选择的期限内（withinPeriod） 通行码匹配（passcodeMatches） 释放（release） 审计结果（auditOutcome） 拒绝原因（refusalReason） 注释
    1 true 任意 任意 false 4 withdrawn STD-ACC-001（撤销）：已撤回的链接不释放任何内容；该尝试会被记录日志。
    2 false false 任意 false 4 expired STD-ACC-001（有效期）：在持有人设定的期限之外打开的链接不释放任何内容（J4：2026-10-26 至 2026-11-09，Consent TrustDemoJ4Consent）。
    3 false true false false 4 wrong-passcode STD-ACC-001（通行码）：错误的通行码不释放任何内容，并在本国记录日志（AuditEvent TrustDemoJ41WrongPasscode）。
    4 false true true true 0 — 清单被释放，访问被记录日志（AuditEvent TrustDemoJ41Access）。

    TD.DT.06 接收方是否跟随该 VHL？

    对于某一个扫描的 VHL，决定接收方是请求清单，还是将该家庭的记录当作纸质记录对待。

    • 服务于：J4.1 在国外的医疗服务点读取家庭成员的记录：验证 HCERT 并读取键 5 处的 VHL（Task_Verify）；HCERT 已验证？（Gateway_Verified）；未验证：按纸质记录对待（Task_Unverified）；请求清单（ITI-YY5），已签名（Task_Fetch）
    • 需求：STT-VER-001，STT-VER-008，STT-VHL-009，STT-VHL-005
    • 数据元素：TD.J41.DE01 请求时间
    • 示例中：Provenance TrustDemoJ41Received
    • 可计算形式：PlanDefinition TrustDemoDT06；源文件 vhl-follow.dmn，命中策略 FIRST
    # HCERT 验证结果（result） VHL 已过期（vhlExpired） 下一步（next） 注释
    1 failed 任意 treat-as-paper STT-VER-008：类型化的结果会指明步骤和原因，例如缓存的信任列表中缺少某个 DSC（STT-VER-006）。临床医生记录其未被验证的原因。
    2 verified true treat-as-paper STT-VHL-009：不跟随已过期的链接。
    3 verified false fetch 通过 ITI-YY5 并使用 HTTP 消息签名（HTTP Message Signature）请求清单（STT-VHL-005）；随后门户应用 TD.DT.05。Provenance TrustDemoJ41Received。
