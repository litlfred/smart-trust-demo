    The VaxLink walkthrough (source) shows sample FHIR payloads in its payload drawer and on its device screens S1 to S8. This page maps each of them to the example in this guide that materializes it, so the walkthrough can load the published examples instead of its own copies.

    Every example is published twice: as a page, and as raw JSON at a stable URL the walkthrough can fetch (https://litlfred.github.io/smart-trust-demo/<Type>-<id>.json). They are FHIR R5, as this guide is.

    Country profiles

    Each country records only what its own step needs, so the guide has a small profile per country where the two differ. Each profile’s description says how it is used in the journey and why its constraints are there. These are demonstrator profiles: they show what each step relies on and are not a ministry’s national specification.

    Country Moment Profile Why it is there Examples
    Thailand J1 TrustDemoThPatient The birth hospital’s newborn: a hospital number, since a baby of Lao parents has no Thai citizen id. TrustDemoThSomsack
    Thailand J1 TrustDemoThImmunization A birth dose with every field the signed DVC (HCERT) carries: product, date, lot, dose number, performer. TrustDemoJ1HepB, TrustDemoJ1Bcg
    Thailand J4.1 TrustDemoThVhlReceipt What the Thai clinic keeps when it views a Lao summary through a VHL: viewed, not copied. TrustDemoJ41Received
    Lao PDR J2 TrustDemoLaoPatient The child the CHW registers, under a temporary id until civil registration catches up. TrustDemoSomsack
    Lao PDR J2b TrustDemoLaoHousehold The household roster, which is how a CHW notices a missing newborn. TrustDemoHousehold
    Lao PDR J2b TrustDemoLaoRegistration The answers on the offline registration form (Structured Data Capture), kept so the extracted records trace back to them. TrustDemoJ2Registration
    Lao PDR J2b TrustDemoLaoReportedImmunization A foreign dose read without verification: primarySource false, the family as source, not counted by the schedule. TrustDemoJ2HepBReported, TrustDemoJ2BcgReported
    Lao PDR J2b TrustDemoLaoReferral The CHW’s referral to the clinic, pointing at the reported doses to verify. TrustDemoJ2Referral
    Lao PDR J3a TrustDemoLaoDvcVerification Who verified which DVC against the GDHCN trust list, and which reported doses it replaced. TrustDemoJ3Verification
    Lao PDR J3 TrustDemoLaoImmunization A dose on the national schedule: the Lao EPI code is required, and a foreign product code is kept beside it. TrustDemoJ3HepB, TrustDemoJ3Bcg, TrustDemoLaoPenta1
    Lao PDR J4.1 TrustDemoLaoVhlAccess Every VHL access logged at home, refusals included (IHE BALP pattern). TrustDemoJ41Access, TrustDemoJ41WrongPasscode

    The payload drawer

    The keys of the walkthrough’s MOCK_FHIR_RESOURCES (src/data/storylineData.ts) and the example that replaces each one:

    Key Type Example What changed
    patient Patient TrustDemoSomsack (json) Temporary-id system is this guide’s (http://smart.who.int/trust-demo/sid/lao-temporary-id), not a ministry URL.
    group Group TrustDemoHousehold (json) R5: membership = enumerated replaces actual; the household code is FAMMEMB with the text “Household”.
    immunizationHepB Immunization TrustDemoJ3HepB (json) Both codings, as on the walkthrough’s payload; plus CVX 08. The product and schedule code systems are this guide’s illustrative stand-ins.
    serviceRequest ServiceRequest TrustDemoJ2Referral (json) Code is SNOMED CT 3457005 (patient referral) with the walkthrough’s text; the verification reason stays in reason.
    provenance Provenance TrustDemoJ3Verification (json) Verifier, enterer and author agents; the DVCs as source entities and the reported doses as removed. The COSE signature stays in the DVC rather than in Provenance.signature.
    auditEvent AuditEvent TrustDemoJ41Access (json) R5 shape: category, code, outcome.code; the receiver is the requestor, the Lao gateway the custodian and observer. The passcode is never logged.
    cborPayload (not FHIR) — The DVC payload is an HCERT (CBOR/COSE), not a FHIR resource; its logical model is smart-trust-phw’s DVCMinPreQual. It waits for bean ig01 before it is an example here.

    What the examples change from the walkthrough’s copies

    • Code systems. The walkthrough’s product codes (vp-hepb-peds-monovalent and so on) and Lao schedule codes (LAO-EPI-HEPB-BD and so on) are illustrative. They are defined here as the code systems TrustDemoVaccineProduct and TrustDemoLaoEpiSchedule, marked experimental, under this guide’s canonical, so no URL implies a real ministry or a real WHO code system.
    • Countries. Thailand is played on the GDHCN DEV network by test participant XXR and Lao PDR by the fictional XXH. Neither is a production key.
    • The passcode. The walkthrough shows 4829 on screen. No example stores a passcode: the consent and audit records say only that one was checked.
    • Dates. As in the walkthrough: birth 2025-10-28, J2 2025-11-18, J3 2025-11-25, the Lao doses 2025-12-10 and 2026-07-28, the trip 2026-10-28.
